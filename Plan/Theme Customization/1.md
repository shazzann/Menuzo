# 1. PROJECT CONTEXT

Menuzo is a SaaS platform that allows restaurant owners to create, manage, and customize their digital restaurant menus.

Restaurant owners access a Shop Dashboard where they can manage their menu items, categories, restaurant settings, and appearance.

One of the existing features is the **Theme Customization System**, located within the Settings section of the Shop Dashboard.

The existing interface allows restaurant owners to manually configure their menu's visual appearance by entering hexadecimal color codes.

However, we have decided to redesign this experience.

### Why are we redesigning it?

Our target users are restaurant owners, not professional designers.

Most restaurant owners are unfamiliar with:

- Hexadecimal color codes
- Color theory
- Color harmony
- The 60-30-10 design principle
- Accessibility contrast ratios
- Choosing complementary colors

Requiring users to manually configure these properties creates unnecessary complexity.

Our new approach is to provide professionally curated color palettes that restaurant owners can select with a single click.

The new experience should be:

**Simple. Visual. Fast. Professional. Beginner-friendly.**

The restaurant owner should not need any design knowledge to create a visually attractive digital menu.

### Expected interaction

1. Identify the clicked theme.
2. Update the currently selected theme.
3. Highlight the selected card.
4. Remove the selected styling from the previously selected card.
5. Update the Live Preview using the selected theme's colors.

### State management

Use the existing frontend state management approach.

Avoid introducing a new global state library.

### Important edge cases

Handle the following:

**Initial page load**

The existing restaurant theme may already have saved colors.

Do not automatically overwrite them with the first curated theme.

**Existing custom colors**

If the current saved colors do not match any curated theme, preserve those colors in the Live Preview.

Do not falsely mark a preset as selected.

A simple non-editable indication such as "Current Theme" may be used if needed.

**Selecting another theme**

The new theme should immediately update the preview.

**Unsaved changes**

If the existing application distinguishes saved and unsaved theme changes, preserve that behavior.

**Save failure**

Do not show a successful save state if the existing save operation fails.

**Invalid palette data**

Prevent invalid or incomplete theme data from breaking the page.
